# 剧本驱动的 Agent 执行合同

## 适用范围与终点

适用于安装衍图后连接 MCP 的 Agent，从用户剧本制作漫剧或真人风格短片。用户只要求复盘规则时整理规则，不重新检查、生成或改写已完成作品。用户要求制作时，以实际可播放成片为终点，执行下面的检查、修正、接续循环；常规创作决定由 Agent 自主处理。

读取当前用户的剧本、已有素材、模型、目标片长及授权。其他电脑使用自己的渠道密钥和本次授权；不继承旧项目的人物、镜号、180秒、六图输入或三/五/十任务并发。最新用户要求优先。

## 1. 让规则进入实际执行入口

先完整读取[布局与单次切图规范](canvas-layout-and-split.md)，这是当前排版、去边替换与清理的唯一执行版本；历史案例不作为指令。镜头规划、关键图、视频及相邻切点检查同时读[换视角与时长连续性](shot-camera-continuity.md)，当前相邻叙事镜头必须换实际视角。

- 外部 Agent：发现当前工具，先通过 skill_search/skill_catalog 找到实际 yingce-film-production，再用 skill_prepare 读取技能。短入口 film-production 必须继续读取指向的完整技能。
- 先读本合同与当前阶段 `phase` 的必需参考，`agents/runtime.json` 明确列出各阶段必读文件和工具；条件性参考按实际封闭空间、模型或剪辑需求加载，不把文中提到的所有可选工具当作同时必需。长文件需要分页补读时，按实际返回的 continuationReads/nextOffset 继续，同一次准备保持 preparationId，补读后再复核准备状态。摘要、文件列表和搜索命中不等于已读正文。
- 保存实际 skillId/versionId/contentHash 和使用阶段；不能声称只改磁盘文件就已更新软件技能库。作者 ZIP 技能用原包更新 API 保持 skillId、新增版本；新电脑由随包技能登记机制进入自己的技能库。当前运行仍用锁定版本。
- Codex 的插件技能入口允许隐式调用；外部 Agent 依照 MCP 的控制说明加载制作技能。单图编辑、规则复盘或只写剧本的请求按其范围执行，不擅自扩成收费整片。
- MCP 提供工具，连接它的 Agent 负责持续执行。客户端结束当前会话时，工具不会自行唤醒会话；记录恢复点。不要把安装成功或自动加载提示词宣称为已验证另一台电脑完成整片。

## 2. 完成门槛与阶段顺序

每阶段建立一份明确的必需产物清单，包含稳定 ID、输入版本、生成/复用来源、实际输出、各项检查和失败原因。不能以空清单、已提交或笼统“都好了”完成阶段。

本步完成 = 必需产物全部存在 + 原任务成功或真实采用素材可复用 + 实际资源可读取 + 每项所需内容检查通过 + 绑定与版本一致。任一缺失、运行中、失败、未审或 uncertain 项，先处理它；依赖它的下一阶段暂不执行。同阶段互不依赖的多项可以按授权并发，画布修改仍用 fresh revision 串行提交。

按正式流程保存以下阶段，具体合同从当前运行读取：

| 阶段 | 必需产物与进入下一步的条件 |
| --- | --- |
| 接收 brief | 剧本原文/版本、目标规格、偏好、可执行授权；未指定时长按对白和节拍估算并记录 |
| 拆解 script_breakdown | 全部故事节拍、人物/场景/道具清单、原句台词、连续性与时长归属 |
| 视觉 visual_design | 统一人物外观、服装、场景与道具设计；封闭空间房型、同一模型与机位依据真实就绪 |
| 粗分镜 rough_storyboard | 完整剧情覆盖、有序 row/shot ID、各镜动作与四个关键状态、必要过渡和粗时长 |
| 资产 asset_package | 全部必需人物、场景、道具参考有真实版本并逐项检查；没有的补齐，合格的复用 |
| 声音 sound_plan | 原句、说话人、对白窗口、原生/配音路径、环境声和配乐计划；需要的实际声线/读本就绪 |
| 锁镜 locked_storyboard | 全部关键图与独立切图检查通过，真实关联逐行核对，时间段、Animatic、总帧数与模型策略一致 |
| 样片 pilot | 有代表性的真实片段和必要衔接已检查，声音按合同实际听审；符合要求的样片直接复用 |
| 逐镜 shot_production | 按故事/依赖采用；全部采用镜头可读取，动作、连续性、规格与必要音频检查通过 |
| 后期 postproduction | 真实时间线、采用区间、必要过渡、完整对白与自然声桥；母版导出并内容检查 |
| 交付 delivery | 真实最终文件完整解码、全片画面和必要声音检查、实测规格与交付合同通过 |

母图和切图属于图片完成门槛：全片本轮所需图片未完成，不进入视频。为每张母图、每张独立切图登记真实资源，不让仅有首帧检查掩盖其他三图缺失。计划中的图片必须进入资产/资源检查清单。当前 schema 支持版本化阶段门时，使用实际构建器生成的 stageGateVersion=1、selfCheckVersion=1 与 pictures:all-ready，读取真实合同；不手写伪造合同或升级旧运行指纹。

新生成与修复后的图片按[AI视觉复查门](visual-review-gate.md)先经实际视觉 AI 审查，再复查身份、身体数量、手指及持物。母图四格分别有具体观察，全部通过才切一次；切图逐张复查后才绑定视频。发现多余手/手臂、换脸或看不清就修复重审，旧证据不放行新资源。每批同时主动完成排版与实际回读，无需用户逐次要求整理。规则更新不重新检查或改写用户已结束的影片。

正式 MCP 新运行默认 `keyframeWorkflow="four_panel"`：每行登记 `keyframeSheetAssetId` 和按时间顺序的四个 `keyframeAssetIds`，五个 ID 指向 `sharedAssets` 中不同的真实复用图片。母图和切图必须已经通过原生图片/分割工具完成，不能在视频计划中重生切图。`firstFrameAssetId` 等于本行切图1；四张切图全在本行 `sharedAssetIds`，母图只用于检查，不作视频输入。第一格同时用于首帧和普通参考时按实际资源只计一次。锁镜检查覆盖每张母图和切图，并包含 `grid_cells_and_cut_edges`；逐资源实际记录四格内容和每张切图边缘。用户明确要求另一图片流程时才选 `direct`，仍受图片检查门槛约束。既有计划不自动加这些字段或重建指纹。

`film_get_run`、创建/修改计划与登记检查的返回包含 `continuation`：读取 `readySteps` 做当前可执行工作，`repairSteps` 先查真实缺陷再修复，`waitingTasks` 只查询原任务，`blockedSteps` 列出未完成依赖。用返回的 fresh revision 写入；不把接续指引当作检查已通过。计划阶段可通过 `film_authorize_run` 登记已有用户授权，保留预算、模型和并发范围；确实缺少授权再询问。用户暂停或取消的运行不得通过授权重启。

阶段验收由 Agent 完成，沿用当前授权；缺少实际配置、工具、听审能力或必要费用授权时，说明具体缺口并继续无依赖的可执行工作。不能伪造完成状态放行依赖步骤。

## 3. 文本框、图片 @ 与可见关联

### 提示词的存放位置

图片/视频的实际生成提示词写入目标节点的原生生成文本框，保存 prompt 与实际 composerContent。中文标题可用于组织正文。不要把提示词单独变成文字卡，再连到图片；便捷工具如果会自动这样建卡，改用当前 schema 支持的原生目标节点及其生成入口。

剧本文档、制作简报、台词表和检查记录可以作为文档节点。图片上的剧情文字依照剧本生成；“提示词写在框里”不是要求将提示词烧入画面。

### 每张图片必须实际传入

1. 从已验收素材取得真实 nodeId/resourceId/versionId，明确身份、空间、道具、动作阶段或衔接用途。
2. 在正文对应作用的段落写真实智能 @，绑定该节点；不要只有手打标签或在顶部堆满所有引用。
3. 生图：所需参考图片直接连到目标图片，保留真实 image→image 输入路径。视频：图片可见地关联到对应分镜行，该行连接对应视频，继承其资产与本镜首帧；已有行路径不再重复补 image→video 线。
4. 按真实资源去重，角色信息可多用途共用同一缩略图和输入。不把同一人的不同时刻生成成多个人；四个动作阶段也不是四个房间。
5. 提交前回读原生提示词、智能提及、关联资产、可见线、缩略图、Picture 编号、首帧槽与实际输入顺序，逐一匹配。连线存在不能代替真实请求核对。
6. 参考数量、画幅、分辨率、时长和首尾帧支持以当前渠道合同和实测为准。超上限时修改可行镜头方案或选择用户授权的兼容型号；不静默漏掉需要的图。旧片采用六张唯一图不代表所有模型都只能/都能用六张。

## 4. 四宫格与跨镜衔接

先完成独立人物、场景、道具。按[人物单张设定图与关键内容](character-sheet-and-key-states.md)，每角色采用一张设定图：正/侧/背全身三视图将脸部强模糊至五官不可识别、保留正常头部和发型，同图另有唯一正脸特写。唯一正脸锁身份，三视图锁体型/服装，不另加头像或拆成四张人物资产；剧情脸必须正常。漫剧与写实均服从本片风格，基础资产不是剧情四格。

每镜只采用一张四宫格，四格表达同一条视频的四个关键时刻：开场 → 中间状态一 → 中间状态二 → 结束。逐格说明可见关键内容与剧情/动作/情绪作用，可以是同一事件的重要阶段，不能用四张近似姿态凑数。先按剧情、动作、对白规划连续时间范围与物理过渡，不能机械平均四等分或固定三秒。母图每格检查，再按真实分隔位置切成左上、右上、左下、右下四张。逐张检查无黑/白边、邻格残留、拉伸或必要部位误裁，保存实际像素。

四张采用切图全部进入本镜实际输入，不能替换为四宫格母图。首帧是本镜切图1；切图4指导结束状态。未声明严格尾帧能力时，把它作为普通参考，不谎称尾帧已锁定。

前镜采用切图4传递身份、位置、手持道具、动作和情绪。本镜切图1在这个状态基础上使用新机位，提供新表情、线索、关系或动作信息；人物可以保持同一站位/姿势，不能把上一格完整构图复制过来冒充下一镜首格，也不为区别强制多走一步。相邻镜头对照真实视频出口检查，失败出口不能引导后镜。只有用户明确要求延长同一视频且接口支持，才使用实际末帧作为延长输入。

确认启用 MiniMax H3 时读取官方 h3-prompt-writing 对应模式与本地适配，按实际模式采用官方结构的中文正文：全参考Ref2VA为六段，基础模式为三个字段；每张图在相应动作段真实内联引用。其他模型读取各自指南，不套用 H3 参数。对白保留原句，安排中段完整说完，开头留承接、末尾留词尾与反应。

## 5. 固定空间与持久状态

封闭室内三步必须有实际依据：房型图（尺度、坐标、门窗、连通）→ 一个共享空间模型（模型源/版本及机位表）→ 同模型导出的取景、关键图、切图及视频。已有合格产物复用；几张分别生出来的不同机位图不能叫建模完成。户外开放场景使用环境参考，不强制房型和建模。

登记世界坐标、物体尺寸、承托物、人物路线、相机位置/朝向/焦段和光源。相机投影改变不使人物到桌子的5米变成10米；距离变化必须有实际人物或物体移动。未标定照片不证明精确米数。近景出画/遮挡与凭空消失分开检查，家具、杯子材质、水位、服装、工具数量和身体/头部/视线方向保持剧情状态。

连续跨相邻房间需要真实经过出口的动作或过渡；剧情明确跳时/跳地点可以直接剪切。必要过渡有独立段/采用区间并进入最终时间线，不能只生成后存放在画布旁。

## 6. 实际自检、返工与接续循环

每一步：查真实状态 → 处理原任务 → 读取实际媒体 → 逐项检查 → 记录通过/失败/不确定 → 修受影响部分 → 复查 → 登记完成 → 继续依赖满足的下一步。

- 图片：逐资产、逐母图格、逐切图放大看内容；边界和空间另查。
- 视频：完整解码，再审看实际首帧、动作前中后、说话期间、末态及相邻衔接。普通多图输入不保证指定时刻精确重现，检查实际顺序与流畅性。
- 声音：ASR辅助原句和时间，真实听审才能评价音质、声线、噪声、配乐和词尾；口型还需同时间画面。未听到音轨不能写 passed。按用户要求处理不合适声音，保留有效对白和环境声。
- 工具：film_self_check 与已有质量报告给实际队列/证据；图片局部编辑、深度、姿态、图层、抽帧、音轨提取和剪辑工具按当前 schema 联动。派生诊断图不代替内容结论；不编造未接入能力。
- 返工：记录真实资源、症状、位置/时刻、正确状态、原因证据或原因未知；仍未解决的实际缺陷进入下一版相关段落。保留正确部分和合格素材。重复同一问题时评估更明确参考、局部修改、镜头重设计或剪辑，不能盲目堆长负面词反复收费。
- 恢复：运行中或回执不明仅查询原 taskId/操作ID；确认终态失败且无有效结果后，按已有授权建立新 attempt/retryOf。幂等键用于同次提交重试。历史结果不能覆盖当前采用版。
- 画布：写入前读最新 expectedCanvasId/revision/stateHash，写后回读；显示空白先查真实任务和持久资源，不把显示故障当成生成失败。图像、分镜、视频从左到右分区，文档另区，切图和视频逐个可见；只整理受影响区域。
- 记录：保存剧本/分镜/空间版本、技能/模型能力版本、实际提示词及图片顺序、run/step/attempt/task ID、采用资源、检查与失败、时间线区间、导出文件和恢复下一步。旧脚本与旧计划只作追溯，不能盲重放。

整片完成必须有真实导出文件、完整解码、故事/连续性/节奏和必要声音检查、实际长度与规格。用户默认无字幕；最新明确字幕要求优先。音乐由剧情决定，声桥自然进出。不能把“所有任务成功”或“导出成功”单独当作成片验收。

## 7. 本次公开流程研究的应用

Toon Boom 的前期流程把剧本、设计、分镜、声音和 Animatic 联系起来；Blender Studio 将分镜置于可理解空间的三维环境，再交剪辑校准时长。这里保留同空间机位、先做低成本分镜粗剪再正式视频的顺序，检查故事节拍是否全覆盖、对白是否放得下、转场是否实际进入时间线。

Agent 的调度采用有明确检查点的分步流程：生成 → 真实检查 → 保存缺陷 → 局部修复 → 复核 → 采用。后端持久运行保存事实，工具给下一动作，阶段合同拦截缺项。阅读回执仅证明返回过对应版本内容；媒体任务成功仅证明生成完成，两者均不能冒充内容质量通过。

参考：[Toon Boom 前期制作](https://learn.toonboom.com/modules/animation-workflow/topic/pre-production)、[Blender Studio 分镜流程](https://studio.blender.org/tools/artist-guide/pre-production/storyboard)、[Anthropic 分步流程和检查门](https://www.anthropic.com/engineering/building-effective-agents)、[LangGraph 持久状态方法](https://docs.langchain.com/oss/javascript/langgraph/persistence)。这里采用其方法，不为此安装额外框架。成片质量仍需真实检查，客户端关闭后仍需重新连接接续。
